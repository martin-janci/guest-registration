# M9 — Full i18n (en / sk / cs) with next-intl

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use `- [ ]` checkbox syntax.

**Goal:** Ship full translation parity with the legacy Flask app — English, Slovak, and Czech — across every user-facing surface (guest self-registration, housekeeper UI, admin UI, emails, invoice PDF), plus a locale picker.

**Architecture:** `next-intl` with the App Router `[locale]` segment. Default locale is **`sk`** (primary audience: Slovak hosts). Locale-less URLs (legacy guest links in past emails) redirect to the preferred locale based on `Accept-Language`. A tiny `Locale` component in the shell lets users switch; selection persists in an `NEXT_LOCALE` cookie. Emails and PDFs receive an explicit `locale` arg so they render in the recipient's language (guest language inferred from the registration email domain + browser hint; admin invoices always `sk` unless the client is flagged `en`).

**Tech Stack:** `next-intl@^3`, ICU message catalogs (`messages/{en,sk,cs}.json`), middleware-based locale detection.

**Branch:** `m9-i18n` (cut from `refs/tags/v0.1.1`).
**Prior state:** `v0.1.1` — 139/139 tests, 3/3 E2E, typecheck + Docker clean.

## Scope

**In M9:**
- `next-intl` installed + `i18n.ts` config + `src/middleware.ts`
- App restructured under `src/app/[locale]/…` (all existing routes moved)
- `messages/{en,sk,cs}.json` ICU message catalogs
- **Every** `.tsx` under `src/app/` + `src/components/` converted to `useTranslations()` / `getTranslations()`
- Email templates accept `locale` and render localised copy (admin-registration, guest-confirmation, guest-approved, invoice-sent)
- Invoice PDF renders in the recipient's locale (Slovak VAT terms: *základ dane*, *sadzba DPH*, *celková suma* — the legal defaults)
- Locale picker in admin sidebar + a compact `<LangSwitch />` on public pages (login, /register/[code], /gdpr)
- Middleware auto-detects locale from `Accept-Language` on first hit; persists explicit choice in `NEXT_LOCALE` cookie
- Unit tests for locale detection; one E2E per locale verifying the guest flow renders correctly
- `<html lang={locale}>` set dynamically in the locale layout

**Out of M9 (deferred):**
- RTL support (no RTL language in scope)
- Pluralisation rules beyond ICU defaults
- Pulling actual legacy `.po` strings from the NAS container (we write fresh catalogs; legacy wording is a reference via the `ARCHITECTURE.md` screenshots, not a blocker)
- Locale-specific number/date formatting beyond what `Intl.*` gives us for free
- Admin-side per-property *"send emails in X language"* setting — v0.3

**Default locale rationale:** `sk` — the primary audience are Slovak hosts managing their own properties; English is a second-class citizen for international guests. The cookie `NEXT_LOCALE` overrides detection once set.

export default getRequestConfig(async ({ requestLocale }) => {

import { ReactNode } from 'react';
import { NextIntlClientProvider } from 'next-intl';
import { getMessages, setRequestLocale } from 'next-intl/server';
import { notFound } from 'next/navigation';
import { locales, isLocale } from '@/lib/i18n/locales';
import '@/app/globals.css';    // adjust if globals live elsewhere

export function generateStaticParams() {
  return locales.map((locale) => ({ locale }));
}

interface Props {
  children: ReactNode;
  params: Promise<{ locale: string }>;
}

export default async function LocaleLayout({ children, params }: Props) {
  const { locale } = await params;
  if (!isLocale(locale)) notFound();
  setRequestLocale(locale);
  const messages = await getMessages();
  return (
    <html lang={locale}>
      <body>
        <NextIntlClientProvider messages={messages} locale={locale}>
          {children}
        </NextIntlClientProvider>
      </body>
    </html>
  );
}
```

import enMsgs from '@/../messages/en.json';
import skMsgs from '@/../messages/sk.json';
import csMsgs from '@/../messages/cs.json';
import { defaultLocale, type Locale } from '@/lib/i18n/locales';

const catalogs = { en: enMsgs, sk: skMsgs, cs: csMsgs } as const;

type EmailDict = typeof enMsgs extends { email: infer E } ? E : never;

export function emailDict(locale: Locale | undefined): EmailDict {
  const messages = catalogs[locale ?? defaultLocale] ?? catalogs[defaultLocale];
  return (messages as any).email;
}

export function pickLocale(hint: string | undefined): Locale {
  if (hint === 'sk' || hint === 'en' || hint === 'cs') return hint;
  return defaultLocale;
}
```

## Task 10: Fill sk + cs translations

**Files:** `messages/sk.json`, `messages/cs.json`

- [ ] **Step 1: Copy EN keys → translate every value**

Hand-translate all strings. Slovak is native-audience, Czech is secondary. Keep placeholders (`{name}`, `{count, plural, …}`) verbatim.

**Translation guidelines:**
- Use Slovak verb infinitive in buttons: *Uložiť*, *Zrušiť*, *Odstrániť*.
- Formal addressing (*vy* form) for guest-facing copy; informal (*ty* form) is too casual for a legal registration context.
- Slovak tax terminology in invoice PDF is fixed by law — **do not paraphrase** (use `pdf-dict.ts` values as-is).
- Czech: same formal tone; use Czech-specific forms (*Uložit*, *Zrušit* — note no háček over `S` in Czech imperative endings; they differ from Slovak).

- [ ] **Step 1: `<LangSwitch />`**

Compact dropdown; each option is a `<Link locale="…" href={currentPathname}>…</Link>` from `@/lib/i18n/link`.

```tsx
'use client';
import { useLocale } from 'next-intl';
import { locales } from '@/lib/i18n/locales';
import { Link, usePathname } from '@/lib/i18n/link';

const labels = { sk: 'Slovenčina', en: 'English', cs: 'Čeština' } as const;

export function LangSwitch() {
  const current = useLocale();
  const pathname = usePathname();
  return (
    <details className="relative">
      <summary className="cursor-pointer rounded-md border border-border px-2 py-1 text-sm">
        {labels[current as keyof typeof labels]}
      </summary>
      <ul className="absolute right-0 top-full mt-1 w-40 rounded-md border border-border bg-surface shadow-sm">
        {locales.map((loc) => (
          <li key={loc}>
            <Link locale={loc} href={pathname} className={`block px-3 py-1.5 text-sm ${loc === current ? 'bg-surface-2 font-medium' : ''}`}>
              {labels[loc]}
            </Link>
          </li>
        ))}
      </ul>
    </details>
  );
}
```
